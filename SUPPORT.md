# support

tekir is an early-stage project maintained by one person. there is no support
team and no guaranteed response time.

## where to go

| you have | go to |
| --- | --- |
| a reproducible bug | the [bug report form](https://github.com/tekiristanbul/tekir/issues/new/choose) |
| a product or community idea | [github discussions → ideas](https://github.com/tekiristanbul/tekir/discussions) |
| a prototype, concept, or experiment to share | [github discussions → show & tell](https://github.com/tekiristanbul/tekir/discussions) |
| a security vulnerability | `security@tekir.istanbul`, privately — see [`SECURITY.md`](SECURITY.md) |
| a privacy question or request | `privacy@tekir.istanbul` |
| a question about using the app | `support@tekir.istanbul` |
| anything else | `hello@tekir.istanbul` |

## what to expect

- bug reports are welcome and read. include a minimal reproduction, expected and
  actual behavior, environment details, and evidence with secrets, personal
  data, and precise private locations removed.
- ideas in discussions are welcome for conversation. they are not commitments
  and may not be accepted or scheduled.
- concrete feature requests and implementation work are handled through
  maintainer-created issues, not through discussions. see
  [`CONTRIBUTING.md`](CONTRIBUTING.md).
- github issues are not a support channel. blank issues are disabled on purpose.
- never post secrets, credentials, phone numbers, personal data, or precise
  private locations in a public issue or discussion.

## want to contribute instead

read [`CONTRIBUTING.md`](CONTRIBUTING.md) for how work is accepted, and
[`GOVERNANCE.md`](GOVERNANCE.md) for who decides what.
