# v0.2.0 draft release notes

status: draft for release preparation as of august 7, 2026. this document is not a publication record and does not imply store or web rollout approval.

## highlights

- application-state behavior now follows the approved shared contract across the app: initial read spinners wait 400 ms, retry affordances are consistent, mutation feedback appears immediately, duplicate submissions are blocked, and reduced-motion users get settled non-animated states.
- discover and notifications now cover their approved empty, loading, permission, and error states, and the map covers its approved loading, empty-radius, error, and location-permission states (#118, #121/#124) instead of falling back to generic blanks or missing affordances.
- the map screen reaches full visual parity with the approved design references: search field, needs-help filter chip, and the location-permission block (#121).
- cat-profile reaches visual parity: per-status action chip colors, on-photo follow button, name placement, three-stat header, timeline author avatars, and images-only media tab/archive/cover-photo counter (#121, #133).
- badges, add-cat, and other normal-state screens close their remaining source-level parity gaps against the approved prototype (#121, #126).
- prototype and design residue is inventoried; unused artifacts removed, historical references marked apart from authoritative ones (#121, #132).
- add-cat preserves typed form data after failures, shows upload progress, and keeps duplicate detection and media steps inside one recoverable flow.
- cat-detail now uses optimistic update saving with rollback on failure, simpler actions, and the approved wider cover-photo presentation.
- splash and brand assets match the approved launch direction, and badge icons meet the contrast correction approved for 0.2.
- cross-screen accessibility regression coverage now checks large text, minimum 44 px tap targets, and reduced-motion behavior across routed app screens.
- ios build/runtime blockers found during first testflight preparation are fixed: google maps sdk now initializes correctly and fails fast with a diagnostic instead of crashing when misconfigured (#129), release builds fail fast instead of silently defaulting to localhost when the api base url is missing (#128), and the full ios setup/testflight workflow is documented (#130).
- the backend (api + notifier) is deployed to production at 0.2.0, migrations applied through 00024.

## user-visible changes

- loading states feel calmer because quick reads no longer flash a spinner.
- save actions acknowledge work immediately and prevent accidental double taps.
- the map and discover flows explain why content is missing and offer retry paths where applicable.
- notifications, profile, badges, and cat detail screens now match the approved 0.2 visual/state contracts more closely.
- add-cat failures are recoverable without re-entering text or reselecting the entire flow from scratch.
- cat profiles show a photo archive, cover-photo counter, and update timeline author avatars.

## deferred work

- video media (cat-profile media tab/archive) is out of scope — no upload/transcoding/thumbnail pipeline exists yet. tracked separately if still wanted.
- offline cache, connectivity persistence, and submission queues remain out of scope.
- dark mode remains out of scope.
- neighborhood caretaker remains out of scope.
- cat not-found remains out of scope.
- no new help categories or help-contract changes are included.
- unrelated api and data-model changes remain excluded.
- centralized mobile runtime config validation (#131) is deferred.
- an original tekir logo (#24) is deferred — no submission received yet.
