# v0.4.2 release notes

status: published august 17, 2026.

covers everything since 0.3.0: the 0.4.0 trust-and-safety and account
work, the 0.4.1 and 0.4.2 reliability fixes, and the android release
readiness that made a play upload possible.

## highlights

- content a user posts can now be reported, and accounts can be blocked with their content filtered out of every list (#240, #244).
- content is classified before it is ever stored or published, failing closed when the moderator is unavailable; in production this covers text today, with image classification held back for the reason recorded under deferred work (#249).
- an account can be deleted from inside the app — terminal, with no deactivation step — releasing the phone number and removing the account's cats, updates, and media (#245).
- a cat's owner can rename or delete it from the cat detail screen (#229, #232).
- profiles carry a profile photo instead of a cover photo (#246).
- the android target is release-ready: the maps sdk key, firebase android app, and upload signing are wired, and a signed bundle is on play internal testing (#265).

## user-visible changes

- short video updates default to muted, with an explicit sound toggle before publishing (#223).
- video thumbnails decode a real frame instead of a placeholder (#226).
- the update media picker's actions were simplified (#222).
- map markers are twice as large, and pins that sit on top of each other are all reachable (#248, #254).
- the map opens on an istanbul viewport at launch instead of an empty world view (#239).
- renaming a cat updates the map and discover lists in place, without a refetch (#231).
- large photos no longer decode at full size into memory (#247).
- creating a cat no longer times out on the photo upload (#253).
- a device credential the server no longer recognizes is replaced automatically, and an interrupted add-cat flow resumes (#258).
- tapping the location call-to-action recovers a previously denied permission instead of dead-ending (#263).
- ios builds target iphone only (#187).

## deployment state at release

- api `0.4.1` and notifier `0.2.1` in production; no backend commits outstanding on `main`.
- web `0.4.2` in production.
- android: signed bundle (versionCode 3) on play internal testing. store listing, app content declarations, data safety, content rating, play app signing, and the maps key fingerprints are done; production access needs a 12-tester, 14-day closed test because the developer account is personal.
- ios: in app store review.

## deferred work

- store and website screenshots still come from the 0.3 web build; refreshing them from a real android build is follow-up work.
- offline-first synchronization, dark mode, caretaker/community/moderator expansion, and social profiles remain out of scope, unchanged from 0.3.
- image moderation is off in production (`MODERATION_VISION_MODEL` unset), so photos and videos publish unclassified while text still fails closed — see DEVELOPMENT.md's "image moderation is currently off in production" for why. the cloudflare release-gate smoke suite stays a manual step, not part of ci.

## release validation

- backend: `go build ./...` clean and `go test ./...` green (944 tests) on the release commit.
- app: `flutter analyze` clean and `flutter test` green (676 tests) on the release commit.
- android: `flutter build appbundle` produces an artifact `jarsigner -verify` reports as signed by the upload key, with the maps key substituted into the merged manifest and no advertising-id permissions in it.
- web deployed to production from this release's commit and verified through `version.json` and a production login.
