# v0.2.0 smoke test report

run date: august 6, 2026
result: pass, with the environment caveats noted below

## build under test

- flutter web release build (`flutter build web`, default release mode) at the
  merge state of #119 (commit 67210df), which includes all ten 0.2
  implementation slices (#110–#119).
- served as a static bundle and verified against the local backend api
  (docker compose `api` + `postgres`, `MEDIA_LOCAL_DIR=/tmp/media` override
  so media uploads land on local disk).
- `API_BASE_URL=http://localhost:8080` (default), `ANALYTICS_PROVIDER=none`,
  `NOTIFICATION_PROVIDER=fake` — the local defaults documented in
  `app/.env.local.example`.
- no google maps browser key was configured, so map tiles do not render in
  this environment. the map error state and the location fallback banner
  were verified instead; tile rendering itself is covered by the live 0.1
  deployment and is unchanged in 0.2.

## flows verified

each step was captured as a screenshot at the repo root (`smoke-*.png`,
untracked). the numbers below reference those captures.

1. boot and splash into the map tab; location unavailable shows the
   "konum alınamadı — istanbul gösteriliyor" fallback banner and the map
   error surface instead of a blank screen (smoke-01).
2. discover tab, location permission off: explanatory state with
   "ayarları aç" and "tekrar dene" retry affordances (smoke-02).
3. "takip ettiklerim" while signed out: login gate sheet over the
   signed-out state (smoke-04); after sign-in, the empty-following state
   with guidance and a "yakındakilere göz at" path (smoke-05).
4. notifications: quiet-day "aktif yardım çağrısı yok" state (smoke-06).
5. cat detail: 16:9 cover, help banner with expiry, single "+ update"
   primary action fixed over the scroll (smoke-07, smoke-08). the english
   "+ update" label matches the binding design
   (`docs/design/screens/cat-profile.html`) verbatim.
6. per-cat notification opt-in sheet at the approved trigger point
   (smoke-09).
7. update composer: status options, optional note, submit disabled until a
   status is chosen (smoke-10). submitting shows the update immediately
   ("az önce", optimistic row) with the note attached (smoke-11).
8. add-cat: location picker (smoke-12), duplicate detection listing nearby
   cats with photos and a "hayır, farklı bir kedi — yine de ekle" escape
   (smoke-13), photo + optional name form (smoke-14), uploading state with
   the submit action disabled against double submission (smoke-15), and the
   created cat's detail screen (smoke-16).
9. profile: contribution stats, recent contributions, badges entry
   (smoke-17). badge list shows progress with the corrected unearned-badge
   contrast (smoke-18).
10. reduced motion emulated: screens settle to their final states without
    animation; navigation and content remain intact (smoke-19).

## caveats

- map tile rendering was not exercised (no browser maps key locally); the
  error/fallback states were exercised in its place.
- push delivery uses the fake provider; the opt-in flow is ui-state only in
  this environment, matching the documented local default.
- one capture (smoke-03) came out blank due to a transition-frame race and
  was discarded; the state it targeted (login sheet) is covered by
  smoke-04.

## automated coverage

`flutter analyze` and the full widget/regression test suite, including the
cross-screen accessibility regression checks (large text, 44 px targets,
reduced motion), run green on the same merge state via ci on #119.
