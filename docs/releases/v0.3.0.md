# v0.3.0 release notes

status: published august 8, 2026.

## highlights

- expired session tokens now refresh automatically both on app resume from background (#155) and reactively on any request that comes back 401 (#173), instead of leaving the user stuck in a broken signed-in state.
- ios location-permission metadata (`NSLocationAlwaysAndWhenInUseUsageDescription`) is complete, closing the warning apple flagged on the first testflight delivery (#151).
- required mobile runtime configuration is validated at startup with a clear diagnostic instead of failing silently later (#131).
- updates can carry an attached photo or video, picked from the camera or gallery, with preview, remove/replace, upload progress, and retry on failure (#153).
- update media now appears both on the timeline entry and in the cat's media gallery tab, with the gallery correctly distinguishing video (its own player, glyph thumbnail, no cover-photo action) from images (#153, #171, #179).
- updates show the uploader/author's display name, both as an avatar initial and as visible text next to the entry (#154, #169).
- only a cat's owner can change its cover photo, selecting from any photo already in the cat's gallery; other contributors' update media stays attached to their own updates (#156).
- the feedback email's app version is read from the running build at runtime instead of a hand-maintained literal that could drift (#175).
- app version bumped to 0.3.0 (#176).
- web release rebuilt and redeployed from this release's commit.

## user-visible changes

- session expiry no longer requires a force-close/relaunch to recover, in the background or mid-session.
- posting an update can include a photo or video, visible on the timeline and in the cat's media tab.
- every update shows who posted it.
- a cat's cover photo can only be changed by its owner, from an existing gallery photo.
- ios testflight builds no longer carry the missing-purpose-string warning from the first 0.2.0 delivery.
