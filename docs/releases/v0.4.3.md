# v0.4.3 release notes

status: unreleased.

a turnaround release for the app store review that rejected `0.4.2` build 3
on august 18, 2026. it fixes the error the reviewer screenshotted, locks the
orientation for the ipad the review ran on, and carries no other product
work.

## why

the review (submission `04619e00-ce76-4aa1-b82a-0beb14d1f90e`, ipad air
11-inch m3 on ipados 26.6) raised three items:

- **guideline 2.1(a), app completeness** — "the app displayed an error".
- **guideline 4, design** — the layout was called not optimized for ipad.
- **guideline 2.1(a), information needed** — no demo account for a
  phone + otp login.

the app treated "no usable location" as a blocking failure on both of its
main screens, which contradicts what the product actually promises. tekir
is about showing istanbul's cats, and a visitor with no location can still
browse them, read updates, and hand the phone to someone else. two separate
paths reached an error in a review lab:

- denying the permission prompt blocked the map behind a full-screen state
  and emptied both location-aware discover tabs behind a retry-labelled
  error card.
- granting the permission outside istanbul — a reviewer in california, say —
  sent out-of-area coordinates to `GET /v1/cats/discover`, which answers
  `400 invalid area`, and that surfaced as a generic "bağlantı sorunu oldu"
  retry card. the map already guarded against this; discover did not.

an ipad air wi-fi has no gps at all, which makes both paths more likely
there than on a phone.

## user-visible changes

- no location condition blocks a screen or renders as an error any more.
  the map opens on greater istanbul with its cats loaded, and discover's
  nearby and needs-help tabs list cats anchored on the same istanbul
  center (#267).
- when that fallback is in effect, both screens show one shared line —
  "konum yok — istanbul merkezi gösteriliyor" — with a `konum iznini aç`
  action that re-prompts or opens the settings page, whichever the os still
  allows.
- distances are hidden while the fallback is in effect. a figure measured
  from the istanbul center reads as "distance from you" and would be wrong;
  the nearest-first ordering is unaffected.
- a position resolved outside the supported istanbul area now falls back
  like any other unusable location instead of failing the discover query.
- the map's fallback banner is visible for the first time. it had been
  drawn at the search field's own offset and underneath it, so it was
  covered on every build that shipped it.
- the app is portrait-only on every platform, including an iphone-only
  build running on ipad in compatibility mode.

## developer-visible changes

- `LocationPermissionState` (old app-states state 06) is gone.
- permission recovery moved to `core/geo/location_permission.dart` and is
  shared by the map and discover services rather than living on one of them.
- `DiscoverLocationOutcome` gained `DiscoverLocationOutOfArea`.
- `DiscoverLocationTabState` carries the anchor coordinate its page was
  queried against, so a fallback list keeps paging against the same point.

## deployment state at release

- no backend or web changes. api and notifier unchanged from `0.4.2`.
- ios: `0.4.3` build 4 for resubmission.
- android: unchanged from the `0.4.2` bundle on play internal testing.

## review response

- the demo account uses the existing app-review otp allowlist (#184):
  `OTP_REVIEW_TEST_NUMBERS` plus `OTP_REVIEW_TEST_CODE` on the api, and the
  same number and code entered under app review information. no app change.
- guideline 4 is answered with the portrait lock plus a reply noting the app
  has been `TARGETED_DEVICE_FAMILY = 1` since #187, so it runs on ipad in
  iphone compatibility mode. if that is rejected again, the next step is a
  max-width content wrapper and a width-derived media grid on the cat
  detail screen.

## release validation

- app: `flutter analyze` clean and `flutter test` green (684 tests) on the
  release commit.
